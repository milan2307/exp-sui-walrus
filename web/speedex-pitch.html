The Solution
One timestamp. On the blockchain. Both parties read it.
TradeProof records the gate-in moment on Sui — a public, immutable, neutral ledger.
  1. 1
    Shipping line registers the container on Sui A Container Digital ID is created on-chain. The ISO ID (e.g. MSCU9876543) is the object. The timestamp is set by the Sui network — not by any party.
  2. 2
    Gate-in is recorded on-chain When the container enters the terminal, the gate_in() function is called. The Sui blockchain records the exact millisecond. This cannot be changed by anyone — not the shipping line, not TradeProof, not Speedex.
  3. 3
    Demurrage is calculated from the on-chain timestamp Both parties use the same public formula on the same public timestamp. They get the same number. There is nothing to dispute.
demurrage = (days_at_port − free_days) × rate_per_day
// Both parties run this. Same inputs. Same output.
No email. No credit note. No dispute.

Why Other Attempts Failed
TradeLens. we.trade. Contour. Marco Polo. All failed.
We studied every post-mortem. TradeProof is built differently.
What they did wrong
  • Built a platform — one company controlled the network
  • Competitors refused to join (TradeLens: Maersk platform)
  • Banks charged $400–$1,000 per transaction
  • Cold start problem: needed everyone before anyone joined
  • Governance: 12 equal shareholders, no one accountable
What TradeProof does differently
  • Protocol, not platform — open source contracts
  • No company controls the network (Sui does)
  • Two parties solve a problem they both have today
  • No onboarding fee, no membership, no subscription
  • Starts with demurrage — smallest viable pilot

The lesson: The four failed projects tried to digitise the entire industry at once. TradeProof solves one problem first — the one that costs Speedex money every month.
