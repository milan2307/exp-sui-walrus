Authority Portal — What This Does
This portal is for institutional parties: shipping lines, port authorities, customs authorities, and government officials. Each party can only write events they are authorised for — the Move contracts enforce this at the protocol level. Institutional login via zkLogin with government/corporate credentials is planned for Phase 3.

Already live: Port authorities can use the CLI today to call gate_in(), load_on_vessel(), and discharged() directly. This portal is the web interface for that functionality.

Register Container — Gate-In
Records the container's arrival at your terminal on Sui. This timestamp is immutable — once written by a Sui validator, neither party can alter it. The demurrage clock starts from this exact moment.
Container Gate-In — container::gate_in()
Gate-in timestamp will be set by the Sui blockchain clock at transaction execution time — immutable and validator-confirmed.
CLI EQUIVALENT
node scripts/container-testnet.js --iso-id XXXX --free-days 5 --rate 150
📋
Update Container Events
Record the next event in the container's lifecycle. Each event creates an immutable on-chain record. Only authorised parties (shipping line, port authority) should call these.
Container Lifecycle Events
📦
STUFFED
Cargo loaded into container at warehouse/CFS
🚧
GATE_IN
Container entered port terminal. Demurrage clock starts.
🚢
ON_VESSEL
Loaded on board. "Shipped on Board" BL status.
⚓
DISCHARGED
Unloaded at destination port.
🛃
CUSTOMS_CLEARED
Customs authority signed clearance.
🚪
GATE_OUT
Container exited terminal. Demurrage auto-settles.
↩️
RETURNED
Empty container returned to depot.
