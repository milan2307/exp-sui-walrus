The Problem

Trade finance is broken.
And it has been for 50 years.

Three specific, measurable failures that cost the global economy tens of billions per year — all solvable with what Sui already has.

⏱
Demurrage Disputes
Importers are charged for container days at port — but the gate-in timestamp lives in the shipping line's private database. The shipper sets the clock. The importer gets an invoice 60 days later with no way to verify. Disputes are routine. Payment is delayed. Relationships break down.
$20–30B disputed annually
📄
Paper Bills of Lading
A Bill of Lading (BL) is the title deed to cargo — whoever holds the original paper controls the goods. Couriering paper originals from Nairobi to London takes 5–7 days. Original BLs are forged. A single BL can be presented to multiple banks simultaneously. Trade finance fraud is rampant because there is no single authoritative holder record.
$2.4B fraud per year (ICC)
🏚
TradeLens & Contour Failed
Maersk + IBM spent $1B building TradeLens. Shut down Dec 2022. Contour (HSBC, Citi, BNP backed LC platform) shut down Oct 2023. Both failed for the same reason: a platform model where one competitor controls the database. Hapag-Lloyd refused to share data on a Maersk-owned ledger. No privacy, no adoption.
Root cause: trust failure

Why Sui

Sui has three features that make
this impossible to build anywhere else.

We evaluated Ethereum, Solana, and Hedera. None have the combination TradeProof requires. Sui has all five.

🔑
Owned Objects = BL Holder Rights
A Bill of Lading must have exactly one legal holder at any time. On Ethereum, this requires complex ERC-721 contract logic that can be exploited. On Sui, the BL is a Sui object with a single owner. The protocol enforces holder rights — not our contract. Only the current holder can endorse or surrender. This is fundamental — not a feature.
🔒
Seal — Threshold Encryption
The reason TradeLens failed: competitors could see each other's cargo details on the shared ledger. Sui's Seal encryption solves this. BL documents are encrypted client-side before upload to Walrus. Competitors see only "encrypted blob exists." Access is controlled by on-chain AllowList objects — added bank to the LC, bank sees the document. No platform needed.
🪪
zkLogin — No Seed Phrase
The adoption barrier for trade finance blockchain is always onboarding. A clearing agent in Nairobi cannot be expected to manage a crypto wallet. zkLogin converts any Google/Microsoft/Apple account into a Sui address via zero-knowledge proof. No seed phrase. No wallet app. No blockchain training. The clearing agent logs in with their work email. That's it.
🌊
Walrus — Decentralised Document Storage
Full DCSA BL JSON blobs (23 fields) are stored on Walrus — Sui's erasure-coded decentralised storage. The on-chain record stores the hash. The document is on Walrus. Neither TradeProof nor any single party hosts the files. 2-year retention, redundant across validators.
🛡
Confidential Transactions — Private Settlement
Demurrage amounts are commercially sensitive — your negotiated rate with the shipping line is not your competitor's business. Sui's Confidential Transactions use homomorphic encryption: the settlement amount is private, but both parties can verify the math is correct without revealing the number to anyone else.

Key Innovation · payment_escrow.move

DeFi demurrage: the first application
where DeFi solves a real-world pain point.

60-day invoice disputes, eliminated. Works between any importer and shipping line — today, on Sui Testnet.

1
Gate-In (Port Authority writes on-chain)
Port authority calls container::gate_in(). Immutable timestamp recorded on Sui. Demurrage clock starts. Neither party controls this — the blockchain enforces it.
2
Importer Funds Escrow
Importer calls payment_escrow::create(). Deposits max potential demurrage in SUI. Smart contract holds it. Beneficiary is the shipping line's Sui address. No bank involved.
3
Gate-Out (Auto-Settlement)
Container exits. payment_escrow::release() calculates exact owed amount using on-chain timestamps. Exact amount releases to shipping line. Remainder returns to importer. No invoice. No dispute. No 60-day wait.
4
Dispute Window (Optional)
48-hour window to raise a dispute. dispute_dao.move handles arbitration on-chain in Phase 4. For the 99% of non-disputed cases, this step never runs.
// The entire settlement logic — 40 lines of Move public fun release( account: &mut EscrowAccount, clock: &Clock, ctx: &mut TxContext ) { let owed = calc_demurrage( account.gate_in_ms, account.free_days, account.rate_per_day_mist, clock.timestamp_ms() ); let to_pay = balance::split(&mut account.balance, owed); transfer::public_transfer( coin::from_balance(to_pay, ctx), account.beneficiary // shipping line ); // Remainder returns to depositor automatically account.status = STATUS_RELEASED; }
Key point: The formula is public, open-source, and runs on-chain. Both parties use the same input (on-chain timestamp) and the same formula. There is no calculation to dispute.

Architecture

Two portals. One neutral blockchain.
Each party writes only what they are authorised for.

The Move contracts enforce authorisation at the protocol level. A clearing agent cannot write a vessel departure event. A shipping line cannot alter the importer's demurrage calculation.

🚢
Trade Portal — Commercial Parties
For importers, exporters, freight forwarders, clearing agents, and banks. Role selector switches the dashboard between: Importer (demurrage focus), Exporter (BL endorsement), Clearing Agent (document verification), Bank (LC and financing).
Fund Escrow Endorse BL Track Container Verify Documents Trade Finance (Phase 4)
🏛
Authority Portal — Institutional Parties
For shipping lines, port authorities, customs authorities, and government certification bodies. Each writes only events within their authority. All available via CLI today — the web portal is the UI layer.
Register Container Gate-In / Gate-Out Issue BL Customs Clearance IoT/DePIN (Phase 3)
Why this matters for adoption: A shipping line's IT team sees the Authority Portal and recognises their workflow. An importer's finance team sees the Trade Portal and recognises their pain point. They never need to understand the underlying blockchain. The wallets are behind a Google login (zkLogin). The proof is a QR code. The settlement is automatic.
